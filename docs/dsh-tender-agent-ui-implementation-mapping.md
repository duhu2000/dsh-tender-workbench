## 1. 实施原则

- “找机会”“筛候选”“人工定案”和“形成交付”的页面结构、信息顺序、主从布局、控件形态、视觉层级和交互状态以 HTML 原型为强制基线，不是仅供参考的方向稿。
- 真实 Projection、Session、Artifact、Agent、复核和报告契约不因视觉重构改变。
- 一个状态只突出一个主操作；技术标识、内部版本和 revision 不进入业务界面，仅用于日志与自动化定位。
- 现有 React 组件、DOM 结构和 CSS 不构成兼容约束。达到原型要求需要重构时直接重构，不保留旧页面、兼容布局、第二入口或平行实现。
- 原型中超出 MVP 的能力不做静态占位、禁用按钮或假 Toast；允许省略的项目以第 7 节封闭清单为准，不能在实现中继续扩张。
- 功能等价不等于 UI/UX 对齐。每个工作面必须保持原型的区块顺序、组件形态、展开模型、主从列关系和视觉密度；旧组件只有在这些维度一致时才能复用。
- 改动面、共享样式影响和后续页面回归不构成兼容理由。本轮可以让后续页面暂时受影响，但不得为保护旧页面而保留两套 DOM、兼容样式或近似控件。
- 真实验收必须在相同内容宽度、相同页面状态下同时取得原型基线和实现截图，并逐区域记录差异。只有所有非封闭差异归零后，才能恢复“已实施/已通过”状态。

## 3. S5.1“找机会”对齐清单

### 3.1 查询条件

S5.1 必须在唯一查询页补齐下列真实条件。每个可见值都必须进入同一个 `TenderQueryIntentV1`、用户可见消息和对应 qcc 参数；任何暂时无法映射的条件都不得显示为可用控件。

| 条件组 | 必须实现的条件与交互 | 参数边界 |
| --- | --- | --- |
| 查询范围 | 仅招投标、仅拟建项目、组合查询的分段控件；组合查询保留并校验两个分支 | `scope` 与 `tender` / `proposed` 分支严格一致 |
| 公共条件 | 关键词 token 输入；发布时间快捷项、往年年份和自定义区间；省市区级联/搜索/已选 token；本次分析目标 | 关键词最多 10 个；地区最多 20 个且不支持港澳台；目标不进入 qcc 参数 |
| 招投标条件 | 信息类型；随信息类型出现的招标阶段或中标阶段；招采方式；行业分类；招采类型；预算金额；中标金额 | 隐藏分支清空无效阶段/金额；预设和自定义金额统一换算为人民币元 |
| 拟建项目条件 | 项目阶段；审批进度；项目总投资 | 多选值和金额边界直接映射拟建项目 Schema |
| 提交与计划 | 两个来源分别显示实际调用计划；就地校验日期、金额、数量和至少一个有效筛选；已有活动数据时显示替换影响 | 表单、摘要、用户消息、Host Schema 和实际 qcc 参数逐字段一致 |

`smartSort` 虽是底层请求 Schema 的可选字段，但 UI/UX 设计稿没有把它定义为用户查询条件，S5.1 不新增该控件；如需启用必须另行完成产品与参数语义决策，不能借“补齐条件”自行发挥。

查询页面严格沿用原型的“页面标题 → 范围 → 公共条件 → 来源页签/分支条件 → 执行计划 → 唯一提交动作”信息顺序。wide 使用条件区/执行计划双栏；medium 和 narrow 依相同顺序单列，不把执行计划挪到不可发现的弹窗。关键词、地区、分段控件、快捷选项、可折叠高级条件、条件页签、日期/金额输入、校验错误、加载和禁用态均按原型交互实现，并补齐键盘与焦点状态。

### 3.2 数据概况与数据明细

- 数据概况按原型先显示当前任务、关键数量、来源进度和数据披露/异常，再显示唯一“继续筛候选”主操作；局部成功不能伪装成完整成功。
- 数据明细按原型提供来源分段、状态/排序筛选、分页列表和选中记录详情；wide/medium 保持主从关系，narrow 按列表后详情堆叠，主要行操作始终可达。
- 所有统计、记录、链接、空态、失败和部分结果来自真实 Projection/Artifact；原型示例只用于验收布局，不能进入运行时。

## 4. S5.2“筛候选”对齐清单

| 工作面 | 必须对齐的页面与交互 |
| --- | --- |
| 初筛口径 | 三页签始终可见；Agent 建议直接初始化可编辑工作副本；规则列表/选中规则编辑器主从布局；新增、选择、启停、删除和字段编辑有明确状态；不存在建议应用门槛 |
| 页内 Dry Run 影响 | 编辑器后依次显示四项影响条和代表性样本/全局影响与冲突双栏；不出现独立“确定性影响预览”表面；草案变化立即标记结果过期并禁用底部确认 |
| 确定性分类概况 | 五类卡片、处理漏斗/规则覆盖、五项执行审计与警示、分类追溯抽样按原型顺序；抽样固定七列及真实追溯动作 |
| 分类明细与追溯 | 独立子视图包含返回动作、六分类页签、筛选/排序、原型六列表格、分页和单条判定链；行点击/键盘打开详情，不另加动作或状态列 |
| Agent 全量分析 | 唯一范围为全部 `include + observe + manual-review`，`exclude + unmatched` 不进入；多批次直到完整覆盖；结果页无选择框，按原型组织运行进度、四指标、队列/详情和真实当前项目追问 |

筛候选的主动作顺序固定为“确认口径并开始分类 → 让 Agent 分析候选 → 进入人工定案”。确认成功聚焦分类页，分类页主动作发送绑定当前分类 Artifact 的固定 `all-eligible` 分析 Intent，只有完整覆盖后才聚焦 Agent 分析成功页；用户也可整体跳过分析直接进入人工定案。内容区不得再放置平行的下一步卡片。

上述工作面必须同时对齐原型的间距、密度、颜色语义、排版、边框、控件尺寸、选中/悬停/聚焦/禁用/加载/失败状态、滚动边界和响应式折叠。允许把原型示例替换成真实契约支持的一层规则控件，但不能改成与原型信息架构无关的卡片集合或技术状态面板。

### 4.1 分类概况

- 标题区、五个分类卡、漏斗/审计、抽样表和底部动作顺序与 `#view-classification` 一致。五类固定为规则初选、观察、人工复核、规则排除、未匹配；抽样行在完整过滤结果上按该顺序稳定排序后分页。`未匹配`表示没有命中任何已确认规则，不等于技术失败或隐式排除。
- wide 使用五卡单行及 `1.55fr / .75fr` 的“处理漏斗与规则覆盖 / 执行与审计检查”主从布局。审计固定覆盖字段标准化、保守去重与明确关联、规则冲突、用户覆盖、来源与原始值，随后是边界警示。
- 抽样表固定为“分类、项目名称、最终命中规则、其他命中、裁决依据、来源、动作”七列。“查看全部”和“查看追溯”进入同一分类明细子视图并带入分类/记录上下文。
- 表格、返回、警示等原型图标必须使用已启用图标库中语义相同的图标，保持原型尺寸、线宽、文字间距和垂直基线；不得使用 `→`、`←` 文本、手绘 SVG 或无关图标代替。

### 4.2 分类明细与追溯

- 子视图顶部依次为带图标返回动作、标题/摘要和“全部 / 初选 / 观察 / 人工复核 / 排除 / 未匹配”六个单选页签；“全部”列表同样按“初选 → 观察 → 人工复核 → 规则排除 → 未匹配”稳定排序后分页，分类页签内以记录稳定键保持确定次序。从分类卡进入时直接选中对应页签，从抽样行进入时同时选中并聚焦对应记录。
- wide 使用 `minmax(560px, 1fr) 350px` 的列表/追溯布局，工作台内容宽度不大于 `980px` 时按列表、追溯折为单列。列表表格固定为“分类、项目名称、最终规则、冲突、字段披露度、来源”六列，不显示额外动作或状态列。
- 整行点击或 Enter/Space 打开详情，筛选控件和页签不触发行选择。追溯依次显示来源、规范化、规则命中/例外、优先级裁决、当前结果和审计；原始字段动作只有真实数据可读时才出现。
- 分类页签遵循 `tablist/tab/tabpanel` 键盘语义，筛选、分页、返回后焦点与滚动位置均可预期；窄屏表格在自身容器横向滚动，不让工作台根节点横向溢出。

### 4.3 Agent 全量分析编排

- `analysis.request` 只有 `all-eligible`，Client 绑定活动数据、分类 Artifact、规则版本和 Projection revision，不传 `recordRefs`、分类数组或 `batchSize`。Host 从分类结果计算 `eligibleTotal = include + observe + manual-review`，固定排除 `exclude + unmatched`。
- `analysis_next` / `analysis_commit` 以稳定批次循环。每个结果都返回 `eligibleTotal`、`completed`、`remaining`；`remaining > 0` 时 Projection 与 Client 单飞继续为 running，Agent 必须取下一批。只有 `completed === eligibleTotal` 才能显示完成并开放完成态的“进入人工定案”。
- 首批/部分 Artifact 只更新进度，不结束运行。失败、中断、刷新或 Agent 提前停止时保留已提交建议，显示“已完成 N / 总数，剩余 M”，恢复动作继续同一绑定的剩余记录；旧数据或分类已经失效时明确拒绝。
- 工具 Schema、工具描述、结果状态和 Projection 都必须表达循环/完成条件；动态验收需要关闭捆绑 Skill 验证不会在第一批后误报成功。

### 4.4 Agent 分析结果页

- 页面按“标题/真实进度 → 分析边界 → 重点复核、建议关注、暂不建议、截止 7 天内四项指标 → 队列/详情”排列。原型 `142` 只表示示例，不进入 UI 或测试固定值。
- wide 使用 `350px minmax(520px, 1fr)`；工作台内容宽度不大于 `980px` 时按队列、详情单列，约 `700px` 时四指标与信号/证据网格折为两列。正文与工作台既定滚动边界保持一致。
- 左侧队列没有复选框，工具条只有 Agent 推荐、数据来源和排序；不显示“分析选中 N 条”“分析当前分类”、批量分析或任意范围编辑。点击/键盘激活记录只切换详情。
- 右侧依次显示项目 hero 与推荐、四项信号、分析依据网格、来源原文摘录、风险与待核验、能力边界和当前项目追问；字段缺失、无法解析和没有来源摘录分别表达，不补造事实。
- “询问当前项目”要求非空问题，发送绑定当前 Session、活动数据、分类/分析版本和 `recordRef` 的 `analysis.follow-up` 类型化意图。发送中显示真实状态并防重复；回答留在对话中，不改写该记录推荐、分类、复核决定或分析完成度。

## 5. S5.4“形成交付”对齐清单

### 5.1 原型理解与状态映射

S5.4 的直接基线是设计稿 `#view-report`、`.report-hero`、`.report-tabs`、各 `.report-pane`、文件卡样式及对应页签脚本。它表达的是一个结果优先、可浏览的交付工作面，不是“生成按钮 + 两个下载按钮”的工具卡。实施前必须逐项核对原型代码并在浏览器中实际操作；只看实现截图、只比颜色或只验证文件可下载均不算理解和对齐。

原型主要展示交付成功态，真实产品还必须把生成前和生成中状态放进同一视觉体系：

| 状态 | 页面结构 | 主操作与状态规则 |
| --- | --- | --- |
| 未满足数据依赖 | 使用同一页面标题与空态，不渲染模拟交付摘要或空页签 | 引导回真实前置阶段；不提供可点击生成 |
| 可生成完整报告 | 交付范围主区 + 快照摘要侧栏，显示全部已复核 | 唯一主操作“生成完整报告”；补充分析观察为可选生成设置 |
| 可生成阶段性报告 | 同一双栏，待复核数量和覆盖边界就近突出 | 用户必须显式确认待复核范围后，唯一主操作“生成阶段性报告”才可用 |
| 发送/等待/生成中 | 双栏范围保持稳定，动作进度靠近操作；文件状态按格式独立 | Session 写操作单飞；只读浏览仍可用，不显示假成功 |
| 已交付/部分完成 | 原型交付结论 + 快照双栏，随后显示五页签 | 默认聚焦“管理摘要”；文件失败只改变报告文件页签和总体状态，不抹去成功格式 |
| 交付视图读取失败 | 首屏和文件 Projection 状态继续可用，当前页签就地失败 | 明确重试有界视图；已成功文件仍可下载 |

### 5.2 五页签内容与顺序

1. **管理摘要**：按“结果 KPI → 指标解释 → 确定性结论/可选补充观察 → 人工确认结果结构与正式候选截止窗口 → 结论边界”排列。原型的视觉节奏、三列信息块、图表双栏和限制列表保留；无补充观察时省略对应区块并自然闭合间距。
2. **分析图表**：使用原型卡片网格、横条、堆叠条、图例和就地口径说明。至少覆盖确认结果地区、正式候选预算、拟建线索总投资、规则初筛五分类、来源/阶段；只有真实结果事实存在时才显示历史结果/竞争线索。截止窗口使用 S5.3 的“已截止 / 7 天内 / 8-30 天 / 30 天以后 / 不可用”，不得沿用原型旧示例的“8-14 天 / 15 天以上”。金额图由 Host 按当前可确定金额的最小/最大值生成三段漂亮刻度，并在元、万元、亿元之间动态选择单位；跨档/开放区间继续单列。没有可稳定分档金额时显示明确空态，不渲染零计数色条或固定阈值图例。
3. **确认候选**：展示同一快照确定性选择的最多 10 条近期需核验记录，保持原型标题、说明、表头优先级和页脚口径。正式招投标与拟建项目分别显示采购人/建设单位、预算/总投资、截止/更新时间与阶段；未披露、无法解析、未分析、未备注和无可用来源链接分开表达。
4. **报告文件**：先说明同一不可变快照和独立文件状态，再显示 Excel/PDF 两张文件卡。文件名称、生成时间、可用大小/页数、目录摘要、状态、下载和失败重试均来自真实结果；Excel 目录使用 S5.3 实际 Sheet，PDF 描述使用实际 4-6 页结果型结构。
5. **版本与溯源**：保留原型页签名称和溯源卡片层级，展示当前查询/来源覆盖、规则初筛、补充分析覆盖、人工确认范围、统计与能力边界及当前文件。删除原型中的 R2 多版本列表、版本比较和再生成入口，不用禁用控件占位。

页签必须是真实的单选 Tab 组件，视觉选中态与 `aria-selected` 一致，支持左右方向键、Home/End 和可见焦点。页面切换只改变当前 Session 的临时浏览状态；刷新默认回到管理摘要，Session 切换必须清空旧页签内容和进行中的读取，不把页签选择持久化为业务事实。

交付后的固定底部动作同样属于原型结构：次操作“查看数据快照”打开当前交付溯源，主操作“查看报告文件”打开文件页签；在对应页签已经选中时只聚焦该工作面，不发送消息或创建新事实。正文只在工作台内容区滚动，工作台标题、四阶段导航和底部动作保持可见；不能改成整页滚动后让下载/重试离开可达范围。

### 5.3 数据与实现边界

- 新增 `ReportDeliveryViewV1` 共享 Schema，由 Host 从 `ReportDatasetV2` 确定性裁剪，包含指标定义/值、分布、金额分布、最多 10 条近期记录、已校验补充观察、局限和必要展示元数据；Client 不重新计算统计。
- 在既有同源、loopback、Session header、Artifact token 保护下增加 `final-snapshot` 专用 `/report-view` 读取；不下载最多 20,000 行的完整快照，不把完整数据或叙述复制进 64 KiB Projection，也不产生第二个可变报告状态。
- 原型示例数字、文件大小、页数、时间、内部 id 和英文状态全部由真实事实替换。内部引用只用于请求绑定、日志和测试，不进入页面主层级。
- 摘要、图表、近期记录、Excel 和 PDF 必须能追溯到同一个 `finalSnapshotId`；失败格式重试不刷新交付视图、不改变叙述、不重排记录。
- 有界视图的读取失败与文件下载/生成失败分别建模；重试摘要不能触发报告生成，重试文件不能重新查询或创建新快照。

### 5.4 响应式与视觉细节

- wide（工作台内容宽度大于约 `980px`）：交付结论/快照按原型 `1.35fr / .65fr` 保持主从双栏；六个 KPI 单行，三项解释/补充观察按三列，图表和两张文件卡按两列。
- medium（工作台内容宽度约 `700-980px`）：原型在此把交付结论/快照、图表、文件和溯源网格依次折成单列，但六个 KPI 仍保持单行高密度；不得提前改成与原型无关的卡片流，也不得缩小字体掩盖溢出。
- narrow（工作台内容宽度不大于约 `700px`）：首屏保持“结论在前、快照在后”，KPI 与补充观察变为两列，图表/文件/溯源保持单列；约 `520px` 时四阶段导航允许受控横向滚动，五个交付页签保持一行可达，底部说明隐藏但“查看数据快照 / 查看报告文件”两个动作保留。候选表改为带字段标签的记录块或受控横向表，不截断下载/重试操作。
- 所有宽度都对齐原型的间距、排版、圆角、边框、语义色、图表比例、状态位置、hover/focus/disabled/loading/error 和内容滚动边界。长中文标题、真实文件名、两位以上统计值和空/零值不得引发布局跳动或文字遮挡。

## 6. S5.5“人工定案与筛候选补充对齐”中的人工定案清单

S5.5 的“筛候选”补充范围以第 4.1-4.4 节为准；本节收口“人工定案”页面。两部分必须在同一次迭代中实现和动态验收，不能只完成复核页后把 S5.5 标记为完成。

### 6.1 人工定案原型基线与封闭增强

S5.5 的直接基线是设计稿 `#view-review`、`.review-progress`、`.review-summary`、`.review-layout`、`.review-filter-bar`、`.bulk-bar`、`.review-detail-card`、`.decision-segment`、`.review-audit`、`.snapshot-ready` 及 `review` 阶段的固定底部动作。页面顺序固定为“标题与进度 → 复核边界提示 → 五项汇总 → 候选队列/逐条复核主从工作区 → 固定底部进度与报告入口”。当前 `TenderReviewView` 的简化工具栏、非原型列、详情层级和刷新即重置的状态管理都不构成兼容目标。

S5.5 在原型之上只增加三项已批准增强：

1. 在候选复核队列内增加“待复核 / 已复核”两个真实页签，解决两类记录默认混排的问题。
2. 把原型活动筛选条中隐含的“排序：Agent 推荐”提升为可操作的排序选择器，并把推荐优先设为默认排序。
3. 真实 Projection/Artifact 更新时保持未受影响的选择、焦点和滚动锚点，解决保存一条决定后整个队列重挂载的问题。

这三项只能嵌入原型既有队列工具区，不得改变页面区块顺序、宽屏主从列关系、七列表格、右侧详情层级或固定底部动作。除本节和第 7 节的封闭差异外，不能以“效率优化”名义继续增加抽屉、卡片列表、兼容表格或第二套复核页。

### 6.2 汇总、队列分区与默认排序

- 标题右侧显示 `已复核 N / 总数` 和同一比例的进度条；五项汇总依次为复核候选、确认候选、观察、排除、Agent 建议。所有数量来自当前 Projection，同一记录只按用户决定进入一个复核结果计数。
- 队列页签固定为“待复核 {pending} / 已复核 {reviewed}”，其中 `reviewed = confirmedCandidate + watch + exclude`。首次进入且 `pending > 0` 时默认打开待复核；首次进入且 `pending = 0` 时默认打开已复核。处理最后一条待复核记录后留在待复核空态并显示完成提示，不在保存瞬间强制切页。
- 待复核页只包含 `pending`；已复核页只包含非 `pending`，并可继续按确认候选、观察、排除细分。不存在把全部决定重新混在一起的默认“全部候选”页签。
- 默认“推荐优先”必须由 Host 对完整过滤结果排序后再分页，顺序固定为 `priority-review`（重点复核）→ `watch`（建议关注）→ `not-recommended`（暂不建议）→ 未经 Agent 分析；同等级以稳定的来源记录顺序/`recordId` 收口，刷新、重复请求和分页不得漂移。
- 排序选择器至少提供推荐优先、时效优先和金额排序。时效排序对正式招投标使用有效截止时间，对拟建项目使用最近公开更新时间，并把不可用值稳定放在末尾；金额排序使用规范化可比较值，未披露、无法解析、跨档或开放区间不当作零。任何排序都必须在 Host 过滤后、分页前执行，禁止 Client 只重排当前页。

### 6.3 筛选与批量操作

队列工具区沿用原型的紧凑两层结构。第一层依次提供搜索、Agent 推荐、截止/阶段、地区、排序和高级筛选；已复核页额外提供用户决定。高级筛选按原型提供初筛分类、公告/项目阶段、金额、招采方式、招采类型、命中口径、风险标记和字段披露度。活动筛选以可移除标签显示，切换队列页签不静默丢弃仍适用的筛选。

- 搜索覆盖项目名称、采购人/建设单位和可见初筛口径名称，不搜索内部 Artifact、command 或 revision id。
- 地区、阶段、招采方式、招采类型和金额只使用规范化项目中实际披露的来源事实；选项由当前数据确定性生成，不把原型示例地区或区间硬编码为业务数据。
- “关键待核验”和风险筛选只消费经过运行时校验的结构化项；不得从 Agent 原因、用户备注或公告正文做模糊猜测。字段披露度由 Host 的固定来源字段注册表计算，未披露与无法解析分别计数，不表示来源准确率。
- 批量条固定为“全选当前页 / N 条已选 / 设为确认候选 / 设为观察 / 设为排除 / 取消选择 / 所有批量操作均可撤销”。MVP 不把全选当前页伪装成跨页全选；跨页批量仍属于 R1。
- 批量命令始终发送显式、去重的 `recordRefs`；复选框点击只改变选择，不触发行详情，行点击或 Enter/Space 打开详情。批量选择和逐条编辑保持两套局部状态，任何一方都不能覆盖另一方的决定或备注。

### 6.4 七列表格与逐条复核

候选表格固定使用原型列和信息层级：

| 列 | 必须显示的真实内容 |
| --- | --- |
| 选择 | 当前页复选框；表头为全选当前页 |
| 项目名称 | 主行项目名称；次行地区、来源专属金额和来源 |
| Agent 建议 | 突出的重点复核/建议关注/暂不建议/未经 Agent 分析标签 |
| 初筛分类 | 初选/观察/人工复核/排除/未匹配，以及存在时的可见口径名称；不展示裸内部规则 id |
| 截止/阶段 | 正式招投标显示截止状态/日期，拟建项目显示项目阶段；未披露与无法解析分别表达 |
| 关键待核验 | 最多两项结构化待核验内容，其余显示数量；未分析不伪造内容 |
| 用户决定 | 确认候选商机或重点前期线索、观察、排除、待复核；明确这是独立用户决定 |

“重点复核”使用成功/高优先语义，“建议关注”使用提醒语义，“暂不建议”使用克制的低优先语义，未分析使用中性语义；标签尺寸、位置和对比度对齐原型，不能退化成普通正文或把整行染成强状态色。用户决定使用另一组徽标和文案，不能让相同颜色暗示 Agent 建议已经成为用户结论。

右侧逐条复核按原型依次显示：来源项目号（实际披露时）、项目标题与来源专属元信息、Agent 建议/原因/证据摘要、四项用户决定分段控件、备注、保存状态、清除决定、保存决定、决策记录和完整/阶段性提示。没有 Agent 分析时显示有界中性说明；没有来源项目号时省略标识，不以内部 `recordId` 占位。历史记录来自当前复核 Artifact 的真实 operation；只有当前可撤销的最近操作显示撤销动作，其他历史不得提供假按钮。

### 6.5 保存后的稳定工作状态

复核事实仍以新的不可变 review Artifact 和 Projection 为准，但 UI 局部状态不能以 Artifact id 作为组件重挂载键。组件身份只绑定当前 Session 和活动数据链；同一活动数据上的 review revision 更新使用请求取消、迟到响应隔离和按 `recordId` 合并的方式刷新行数据。

保存或撤销成功后的规则固定如下：

1. 保持当前队列页签、筛选、排序、页码、展开状态和滚动锚点。
2. 只从选择集合移除本次命令实际处理的 `recordRefs`，其他仍符合当前视图的勾选保持不变。
3. 待复核中的当前记录形成决定后移入已复核；焦点优先落到原视觉位置的下一条，页尾则落到上一条。当前页变空时才把页码收敛到最后一个有效页。
4. 已复核记录修改为另一已复核决定时保持当前详情；清除为 `pending` 时移入待复核并按同样规则定位相邻记录。
5. 加载新 Artifact 时保留现有可见内容并显示邻近刷新状态，不用全页 loading 清空表格和详情。失败时保留旧内容、明确重试，不把写入成功误报成读取失败。
6. 只有 Session、活动数据链或用户主动改变队列/筛选/排序/页码时，才按动作语义清理选择和详情；Session 切换必须立即取消旧请求并清空旧 Session 的局部状态。

### 6.6 “按当前进度生成报告”入口

人工定案阶段固定底部左侧显示“报告只使用用户决定，并明确区分确认候选、观察、排除与待复核”，同时就近显示 `已复核 N / 总数`；右侧保留“撤销最近操作”和主操作“按当前进度生成报告”。按钮和进度在 wide / medium / narrow 均可达，最窄宽度允许说明换行或隐藏长说明，但不能隐藏进度和主操作。

该主操作负责进入“形成交付”的生成前状态，并携带当前 Projection 中的复核范围，不直接发送 `report.generate`。S5.4 继续负责完整/阶段性范围说明、存在待复核时的显式确认、补充观察选项和唯一生成动作。这样保留原型的阶段出口文案，同时不绕过已确认的交付快照与 Session 单飞边界。快速双击只能发生一次导航；未进入 S5.4 的明确生成动作前不得创建消息、命令或快照。

### 6.7 数据与实现落点

- 扩展或直接替换首次发布前的 `ReviewRowsFilterV1` / `/review-rows` 契约，增加队列范围、排序、地区、阶段、金额、招采方式/类型、命中口径、结构化风险和披露度；不保留旧/新并行端点或 Client 兼容分支。
- Host 对完整数据依次执行运行时校验、队列范围、筛选、稳定排序和分页；响应返回过滤后总数、队列计数和有界行展示事实。Client 只发送类型化筛选并从 `unknown` 校验响应，不下载全量 review Artifact 后自行排序。
- 结构化风险标记必须来自类型化 Agent 建议或 Host 可确定事实，例如有效截止是否紧迫；披露度必须来自固定、来源感知的字段注册表。自由原因、用户备注和标题不得作为枚举推断来源。
- `TenderReviewView` 需要接入工作台 `footerTarget` 和只负责打开 delivery 阶段的窄回调；复核页面不持有完整 `ClientContext`，也不直接生成报告。
- `review.apply` / `review.revert` 的持久事件、幂等、同源/Session/token 保护和最近操作撤销语义继续成立。此次 UI 重构不引入第二套复核状态机，也不把筛选、排序、选择、页码或焦点持久化为业务事实。

### 6.8 响应式、键盘与验收状态

- wide（工作台内容宽度大于 `980px`）：按原型使用 `minmax(620px, 1fr) 340px`，队列为主、逐条复核为从，详情 sticky；五项汇总单行，表格在队列卡内部横向滚动。
- medium（工作台内容宽度约 `700-980px`）：队列与详情按原型折为单列，详情紧随队列，五项汇总仍保持单行；不能改成详情抽屉或省略原型区块。
- narrow（工作台内容宽度不大于约 `700px`）：汇总为两列，队列在前、详情在后；表格保持原型列并在自身容器受控横向滚动。约 `520px` 时工作台占满可用宽度，阶段导航可横向滚动，标题进度纵向折叠，底部进度、撤销和报告主操作仍可达。
- 待/已复核页签使用 `tablist` / `tab` / `tabpanel`，支持左右方向键、Home/End 和可见焦点；行、复选框、分段决定、高级筛选和撤销都有独立可访问名称，焦点不会因后台 Artifact 刷新回到页面起点。
- 动态验收至少覆盖：全部未分析、部分分析、四种推荐等级、待/已复核切换、推荐优先跨页排序、全部原型筛选、单条与批量保存、保存期间继续勾选其他行、清除决定、撤销、最后一条待复核、阶段性/完整报告入口、读取失败/恢复、刷新、Session 切换，以及同状态的 wide / medium / narrow 原型与真实 DSH Web 逐区截图。

## 7. 唯一允许的 MVP 原型差异

- 不实现“让 Agent 调整草案”的自然语言输入与提交动作。
- 不实现“导入规则”和“复制规则”。
- 不实现嵌套 AND/OR 条件组或完整条件组编辑器；MVP 继续使用当前一层来源/字段范围/OR 关键词/例外/动作/优先级契约。
- 不实现规则版本浏览、版本比较和差异中心。
- “询问当前项目”已纳入 S5.5，必须是第 4.4 节定义的真实类型化交互；不得删除、禁用或用假 Toast 代替。R1 只后置多轮追问历史和更丰富的上下文控制。
- 不实现在线 PDF 预览、多交付版本历史/比较和成功文件再生成；它们属于 R2。S5.4 仍保留原型“版本与溯源”页签，但只展示当前交付依据。
- 原型“用户排除原因 Top 5”依赖当前不存在的结构化人工排除原因，S5.4 不从自由备注猜测分类，也不显示空图；未来只有先增加显式原因契约才可恢复。
- S5.5 在原型候选队列工具区增加“待复核 / 已复核”页签和显式排序选择器；这是解决默认混排和不可操作排序的封闭增强，不得据此改变原型其余结构或增加第三个混合队列。
- 原型脚本中的“选定的初选候选”和静态 `142` 被本次明确产品需求替换为 Host 派生的全部 `include + observe + manual-review`；`exclude + unmatched` 不进入 Agent 分析。该差异只改变真实范围与数量，不允许改变分析页结构、布局或交互。
- 人工定案底部仍显示原型文案“按当前进度生成报告”，但点击后进入 S5.4 生成前范围确认；原型脚本中的直接 `report.generate` 不进入实现，以保持阶段性报告显式确认和补充观察选项。
- MVP 只支持全选当前页和最近操作撤销，不把它们伪装为跨页全选或任意历史回退。历史操作可以只读展示；不可撤销的历史不显示假动作。
- 原型中的示例行业规则、示例数量和模拟数据只表达布局，不是内置业务能力。

除此之外，外部原文入口仍只在 Artifact 返回合法来源链接时显示，不猜测 URL；候选清单仍不表述为 Bid/No-Bid、胜率或企业适配结论。这些是真实数据与产品边界，不是改变页面样式、布局和交互的理由。任何新增差异必须先更新产品与实施文档并获得明确决策。
